# Research continuity component DOM acceptance

Run from frontend:

`RESEARCH_CONTINUITY_BROWSER_OUTPUT_DIR=/tmp/continuity-dom node --import ./tests/e2e/runtime-env.mjs tests/e2e/research-continuity.browser.mjs`

The harness builds this test-only adapter in Vite production mode using the real
ResearchContinuityCard, API client, React DOM and production CSS. The parent only
sets props and mounts/unmounts the component; it does not duplicate request or
rendering logic. The adapter is not a production application route and is not
included in the ordinary application build.

At 1440px and 390px, it verifies stale success/error across campaign and prefetch
changes, obsolete finalizers while a newer request waits, awaiting-batch loading,
unmount, and accessible expansion/collapse of all 13 changes. It records DOM
screenshots and machine-readable results. API traffic is intercepted and only
explicit continuity GET endpoints are admitted. External network and WebSockets
are blocked; there are no real providers, models or formal-state writes.

`--build-only` validates the adapter bundle without launching a browser. It does
not establish DOM acceptance. Browser acceptance must run in supported CI.

The synthetic changes.json was generated by production research_continuity_service
_continuity -> _chain -> compare_evidence against one original evidence record and
one later immutable delta containing nine uniquely claimed additions, two opposed
sources for a shared claim, and a confidence change to the original. Authority
read functions were replaced with synthetic snapshots; no storage/provider calls.
The result has 11 ADDED, one CHANGED and one SOURCE_CONFLICT, in backend sort order.
Fixture contract tests pin this overflow and prohibit write-method admission.
