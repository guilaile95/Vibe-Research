## 使用与验收约束

- 所有需要目标、样本、来源或关联材料的入口均等待用户明确输入；空列表、未配置、无已解决样本及来源缺失是正常状态，不以虚构默认数据填满界面
- 这些入口不自动修改正式 Thesis、Frozen Decision、Trade Ledger 或订单，不把手工材料、演示、模拟模型输出视为真实来源/模型证据
- 日 K 线笔记和事件绑定的签名凭据服务于现有单进程本地使用；重启、过期或不同进程需重读。它们证明服务器观察的内容，不证明供应商真实性或完整历史有效性
- 本轮渲染浏览器验收未完成：已知浏览器启动环境限制未绕过或重复尝试。组件测试、静态合同与生产构建不能代替真实页面运行证据
- 真实供应商、真实模型、自然次日使用、部署与持续产品价值仍需独立验收；离线测试通过不解除这些缺口
- 本轮离线执行使用 Python 3.11 与现有依赖；本地 Node 24 与 CI Node 22 的版本差异需要在验收结果中明示

## 已接入的浏览器 CI 范围

既有 CI 的数据健康恢复场景包含关系钻取，全市场场景包含条件卡版本 / 运行 / 对比。
本轮额外接入三个已存在的离线合成脚本：历史信号实验保存 / 对比 / 重读、事件预期与证据判断、日 K 线键盘 / 日期检查。
这些步骤仅在 CI 浏览器准备成功后执行，采用现有依赖和本机临时服务；接线本身不等于执行通过。
另接入一个显式合成组件工作流套件，覆盖反向 DCF、申报文本、标注、预测日志、目标配置、公告关联，
包含桌面 / 窄屏检查和离线请求审计。它使用实际组件与合成 API，不是完整页面路由或后端持久化验收；
本地仅完成 fixture 编译，实际 DOM 执行证据需由候选提交 CI 建立，不能预先声称通过。
滚动研究仍缺少针对新增交互的实际浏览器场景。组件 Hook 测试由 `npm test` 执行，但不能代替浏览器证据。
旧提交的绿色浏览器任务不证明本轮新增场景；最终 CI 结果必须与候选提交及实际注册场景一起阅读。
