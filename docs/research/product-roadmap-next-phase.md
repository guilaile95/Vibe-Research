## 一、阶段目标

当前项目已经具备每日复盘、资讯雷达、个股数据、自选股、板块研究、持仓管理、研报管理、研究记录和 AI 接入等基础能力。下一阶段不再以增加更多页面和数据入口为主，而是补齐以下闭环：

```text
信息与证据 → 投资判断 → 执行计划 → 实际交易 → 结果复盘 → 判断校准
```

核心原则：

1. 所有投资判断都应可追溯到具体证据和数据时间。
2. 事实、推断、未知项必须分开表达。
3. 系统只提供研究、提醒和决策辅助，不自动下单。
4. 新功能一次只推进一个独立 Draft PR，不并行启动多个大型模块。
5. 金融语义、数据权威链和历史结果必须独立审查。

## 二、优先级总览

| 优先级 | 功能 | 主要价值 |
|---|---|---|
| P0 | 投资逻辑与证据账本 | 让判断可追溯、可更新、可证伪 |
| P0 | 数据健康中心（最小版） | 防止陈旧、残缺或降级数据被误认为实时事实 |
| P1 | 交易流水与决策反馈闭环 | 把建议、实际执行和结果连接起来 |
| P1 | 条件监控与提醒中心 | 将文字条件转成可执行、可追踪的提醒规则 |
| P2 | 账户级风险中心 | 从单票建议扩展到账户整体风险暴露 |
| P2 | 历史回放与决策校准 | 评估判断和信号在不同市场环境中的实际表现 |

## 三、P0：投资逻辑与证据账本

### 目标

为每只股票、行业或主题维护一份持续更新的投资逻辑，使 AI 结论不再是一次性文本，而是有版本、有证据、有失效条件的研究对象。

### 第一版数据对象

```text
EvidenceRecord
InvestmentThesis
ThesisRevision
```

### EvidenceRecord 最小字段

- `evidence_id`
- 关联股票、行业或主题
- 标题与摘要
- 来源 URL / 文件 ID
- 来源类型
- 发布时间、获取时间、数据时间
- 支持的观点
- 证据等级
- `fact / inference / unknown`
- 是否过期或被后续证据推翻

### InvestmentThesis 最小字段

- `thesis_id`
- 研究对象
- 核心观点
- 支持证据 ID
- 反对证据 ID
- 催化因素
- 主要风险
- 失效条件
- 当前状态：`active / weakened / invalidated / archived`
- 创建时间、更新时间

### ThesisRevision 最小能力

- 保存每次投资逻辑版本
- 展示新增、删除和修改内容
- 记录变更原因
- 记录触发变更的证据
- 不覆盖历史版本

### 与现有功能的连接

- 持仓建议引用 `thesis_id` 和 `evidence_id`
- 个股页展示当前投资逻辑和主要证据
- 研报、公告、新闻和研究记录可转为 EvidenceRecord
- 新证据出现后提示投资逻辑可能需要更新

### 第一版不做

- 自动生成不可审计的“综合评分”
- 自动把 AI 推断标记为事实
- 自动修改投资政策
- 自动删除被推翻的历史证据

### 验收标准

- 任一投资结论可追溯到具体证据
- 每条证据有来源和数据时间
- 事实、推断、未知项可区分
- 投资逻辑修改后可查看前后差异
- 失效条件可被后续提醒模块引用

## 四、P0：数据健康中心（最小版）

### 目标

把目前分散在各页面的 `normal / partial / unavailable`、缓存状态和数据时间集中展示，避免用户把过期或不完整数据当成实时事实。

### 最小功能

- 数据源名称
- 最近成功时间
- 数据交易日 / 截止时间
- 当前状态
- 是否 stale
- 是否使用缓存或降级结果
- 覆盖数量
- 最近错误摘要
- 当前是否允许生成持仓建议

### 展示层级

1. 全局数据健康概览
2. 页面级状态
3. 单个组件或数据源详情

### 验收标准

- 能快速识别哪些模块数据陈旧或不可用
- 持仓建议被阻止时能明确显示具体原因
- 不向前端暴露完整异常堆栈或敏感配置

## 五、P1：交易流水与决策反馈闭环

### 目标

将当前持仓快照扩展为完整交易账本，并把每笔交易与当时的投资逻辑、持仓建议和市场环境关联起来。

### 最小交易记录

- 股票代码与名称
- 操作类型：买入、加仓、减仓、卖出
- 成交日期与时间
- 成交价格与数量
- 手续费与其他成本
- 关联持仓建议 ID
- 关联投资逻辑版本
- 计划价格与计划数量
- 实际价格与实际数量
- 未执行或部分执行原因
- 备注

### 反馈能力

- 计划与实际成交偏差
- 建议与实际执行偏差
- 持有期与已实现收益
- 交易后复盘
- 是否遵守原失效条件和风险计划
- 判断正确但执行错误、判断错误但执行合规等分类

### 第一版不做

- 券商自动同步
- 自动下单
- 高频成交明细
- 复杂税务计算

### 验收标准

能够回答：

```text
当时为什么买？
依据是什么？
实际执行了什么？
后来发生了什么？
原判断哪里正确或错误？
是否遵守原计划？
```

## 六、P1：条件监控与提醒中心

### 目标

将持仓建议和投资逻辑中的价格条件、风险条件、催化和失效条件转换为可执行监控规则。

### 第一版支持条件

- 价格达到或跌破指定区间
- 估值进入指定分位区间
- 发布财报、业绩预告或重大公告
- 行业排名出现明显变化
- 投资逻辑关键条件发生变化
- 数据长期不可用或过期

### 提醒记录

- 规则 ID
- 关联股票、投资逻辑和证据
- 触发时间
- 使用的数据时间
- 实际触发值
- 触发原因
- 已读状态
- 冷却时间
- 去重键

### 第一版不做

- 自动交易
- 无来源的 AI 自由生成价格阈值
- 分钟级高频监控
- 短信等付费渠道

### 验收标准

- 同一事件不会重复轰炸
- 提醒明确显示数据时间与触发依据
- 可从提醒跳转到投资逻辑和相关证据
- 可查看历史触发记录

## 七、P2：账户级风险中心

### 目标

从单票建议扩展到账户整体风险识别，但不使用无法解释的单一风险分数。

### 第一版指标

- 单票集中度
- 行业集中度
- 同产业链重复暴露
- 现金比例
- 账户浮亏和回撤
- 盈亏贡献度
- 高相关持仓识别
- 共同投资假设暴露
- 简单情景压力测试

### 情景示例

- 某行业整体下跌 10%
- 大盘下跌 5%
- 某一核心投资假设失效
- 高相关持仓同步下跌

### 验收标准

- 每个风险结论都有计算过程和数据来源
- 能定位风险来自哪些持仓
- 不直接输出自动调仓指令
- 不把历史相关性视为稳定因果关系

## 八、P2：历史回放与决策校准

### 目标

复用现有每日复盘历史和快照比较能力，评估当时判断与后续结果，而不是立即建设复杂回测系统。

### 第一版能力

- 回放某个交易日当时可见的数据
- 展示当时生成的市场判断和明日计划
- 对照次日及后续实际表现
- 标记哪些观察点被触发
- 统计不同信号的后续表现
- 按市场环境分类统计
- 记录结论中的事实、推断和未知项

### 第一版不做

- 自动寻找最优参数
- 基于小样本自动修改规则
- 未来数据泄漏
- 把回放结果包装成可直接交易的策略收益

### 验收标准

- 回放仅使用当时可获得的数据
- 能识别数据修订或后验信息
- 信号统计显示样本数量和适用环境
- 不因少量成功案例得出确定结论

## 九、明确暂缓事项

现阶段暂不启动：

- 券商自动下单或自动调仓
- 全自动量化交易
- 为增加数量继续接入不稳定数据源
- 将未经验证的新数据源设为权威来源
- 大规模路由或目录架构重构
- 继续增加更多板块页面
- 仅靠扩大 Prompt 提升产品能力
- 没有交易流水前建设复杂收益归因
- 没有足够样本前进行策略参数优化

## 十、实施顺序与阶段门

严格按以下顺序推进：

1. 投资逻辑与证据账本
2. 数据健康中心最小版
3. 交易流水与决策反馈
4. 条件监控与提醒
5. 账户级风险中心
6. 历史回放与决策校准

每阶段启动前必须满足：

- 前一阶段已合并并完成稳定分支验证
- 数据模型和 API 契约已经明确
- 关键金融语义已有测试
- 本阶段只建立一个独立 Draft PR
- 未同时启动其他大型候选

每阶段结束必须输出：

- Base / Head SHA
- 变更范围
- 数据模型和 API 契约
- 测试结果
- CI Run
- 已知限制
- 未处理范围
- 是否具备进入下一阶段的条件
